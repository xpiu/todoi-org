Huly — summary, assessment and sources

Summary

Huly puts a project tracker, team messaging, documents, a calendar and time management inside one workspace, so a task, the conversation about it and the document behind it live in the same application. It is aimed at teams who would otherwise run four tools, and it is the broadest single product in this directory.

The tracker is Linear-shaped: issues with sub-issues, components and milestones, moved by keyboard as much as by mouse. Around it sit a shared team calendar, documents, messaging and a virtual office. The calendar is native and central to how the product is meant to be used, but nothing speaks CalDAV or iCalendar to it, so it cannot become the calendar on a phone.

The price of that breadth is the deployment. A Compose file brings up several services with MongoDB or CockroachDB behind them, object storage for files and a search index beside it: more services than anything else in this directory asks you to run, and an ongoing commitment rather than a one-evening install. The code is TypeScript and Svelte, and the repository covers the whole platform rather than the tracker alone.

EPL-2.0 covers that platform, and the July 2026 closure of the hosted service did not touch it. What the closure removes is the vendor’s own instance as a fallback, which is worth weighing against a product this wide. Data leaves through workspace backup and restore tooling plus a plugin and API surface rather than named export formats, and because the workspace holds messages and documents as well as issues, replacing it means replacing several tools at once.

OpenProject — summary, assessment and sources

Summary

OpenProject is classic project management with the agile parts in the same place: work packages, Gantt, boards, budgets and timesheets under one project structure, with roles and permissions underneath. It is the entry a PMO would recognise on sight, and it carries the highest enterprise-features score in this table.

Everything is a work package — task, milestone, bug, feature, risk — separated by type, and each type carries its own form, workflow and status transitions. Projects nest, modules switch on per project, and portfolio views read across all of them. Time and cost tracking are native rather than a plugin, which is rare at this size.

It is a Rails and Angular application over PostgreSQL, shipped three ways: one packaged container with everything inside it, native packages for the usual distributions, or an official Helm chart. The database is the only external service, and upgrades are documented per release. Calendars leave as iCalendar subscription URLs, one per work-package view and one way only; there is no CalDAV to write back to.

The Community Edition and Enterprise add-ons are GPLv3-licensed, while SSO, two-factor authentication and several administration and reporting features belong to the Enterprise editions. The edition table rather than the feature tour is the document that says what you are getting, and the gap between the two is the most common surprise on this project. Exports are CSV, XLSX and PDF, with an OAuth2 REST API for whatever the exports miss.

Plane — summary, assessment and sources

Summary

Plane is a product-development workspace: work items in cycles and modules, grouped under projects and initiatives, with board, list, spreadsheet and Gantt views over them. It reads like Linear or Jira to anyone arriving from either, and it takes the highest mean score in this directory.

The object model is most of the reason for that score. Work items carry custom properties and states, cycles do the work of sprints, modules group feature-sized slices that cut across cycles, and initiatives sit above projects for portfolio work. Views are saved per project or per person, and the spreadsheet view edits in place, so planning does not mean leaving the tracker.

Self-hosting is Docker Compose over PostgreSQL, Redis and MinIO, or a Kubernetes chart for anything larger. That is several services rather than one container, and the operational cost is real, though both paths are documented. There is no calendar interface of any kind, neither CalDAV nor an iCalendar feed, which is the sharpest gap in an otherwise wide product.

Plane is open core and the boundary has moved between releases, which makes the Community Edition’s own feature list the document to read and the pricing page the one to ignore. On the way out there are CSV and JSON exports, a REST API, webhooks, OAuth apps and an MCP server, which is the widest advertised integration surface recorded here.

Redmine — summary, assessment and sources

Summary

Redmine is a configurable issue tracker that has been running projects since 2006: trackers, statuses, workflows and custom fields defined per project and per role, with a plugin ecosystem that has had two decades to fill the gaps. The interface shows its age; almost nothing else about it does.

The configuration model is the product. A tracker is a work type, a workflow is a matrix of role-by-status transitions, and custom fields attach to issues, projects, users or time entries. Subprojects, issue relations and per-project module switches cover most of what newer tools present as headline features. Agile boards are not in core and arrive as a plugin, which is the trade this project has always made.

It runs on Ruby on Rails over PostgreSQL, MySQL or SQLite, from an official Docker image or distribution packages. The stack is ordinary and the upgrade path is documented; plugins are what make upgrades interesting, since each one has to match the Redmine version underneath it. Three supported versions shipped in August 2026, which answers anyone assuming the project is dormant.

There is no first-party hosted service — Planio, Easy Redmine and others sell that. Data leaves as CSV, PDF, XML and JSON, with iCalendar and Atom feeds over any issue query and a full REST API in both XML and JSON. Between standard databases, a documented API and twenty years of format continuity, it has the strongest archival story of the large tools here.

AFFiNE — summary, assessment and sources

Summary

AFFiNE puts documents, an infinite whiteboard and databases in one workspace, with tasks as database views rather than a tracker of their own. The interface is among the most finished in this directory, and the licence underneath it splits in a way no other entry here does.

A page has two modes: a document, and an edgeless canvas where the same blocks sit on a whiteboard alongside shapes, frames and connectors. Databases carry table, board and gallery views, though no calendar, and blocks written in a document can be pulled onto the canvas without leaving the page. The whiteboard has no real peer among the tools here.

The licensing line runs between client and backend. The client is MPL-2.0; the self-hosted backend ships under an AFFiNE Enterprise Edition licence, and multi-admin roles and team management sit in a paid self-hosted tier. That is why sovereignty scores 2.8, the lowest in this table, for a product whose source you can read.

Running it is Docker Compose with PostgreSQL and Redis, which is more machinery than a notes application suggests. Exports are Markdown, HTML, JSON and PDF or PNG over a GraphQL API with WebSocket sync — fine for documents, thinner for structured work. The audience is large for the editor and much smaller for the backend, so self-hosting questions find fewer public answers than the star count implies.

Habitica — summary, assessment and sources

Summary

Habitica wraps habits, dailies and to-dos in a role-playing game: tasks award experience and gold, missed dailies cost health, and parties and guilds carry the accountability a manager otherwise would. It is a motivation system, and it takes the lowest mean score here because it is being measured against project tools.

There are four lists and no views: habits, dailies, to-dos and rewards. A daily repeats on a schedule the interface never draws for you, there is no board, timeline, calendar or timer, and completion rather than duration is the unit. That is the whole interface, and the narrowness is the design rather than a gap in it.

The social layer is where the work happens. Parties run quests that convert task completion into shared progress, guilds carry topic communities, and challenges let one person set tasks for many. It is a social structure rather than an organisational one, with no roles or permissions behind it.

That leaves the self-hosted path thinly travelled: the bugs you hit there have fewer people ahead of you in the queue. Exports are JSON and CSV over a full REST API with user-configurable webhooks, which is more than this category usually offers.

Logseq — summary, assessment and sources

Summary

Logseq is an outliner over plain Markdown and Org-mode files on your own disk, where a task list is a query across notes you already wrote. It takes 5.0 for both sovereignty and portability, which is what a database made of files on your own disk is worth.

Tasks exist as things to book time against rather than cards to move, the calendar view is a time grid by day and week rather than a calendar of work, and there is no board of any kind. Project permissions and client rate masking cover the access model, which is enough for an agency and not for a department.

It is a Meteor and React application over MongoDB, deployed as one container and small enough to run and forget. A first-party hosted service exists and sells hosting rather than features: nothing is reserved out of the AGPL build.

Everything points at the handover. CSV, XLSX and JSON exports and a REST API are there to get time into an accounting system, which is the design goal rather than an afterthought. The counterweight is scale: 497 GitHub stars, the fewest in this directory, and a maintainer group small enough to count — worth weighing against how much of a billing process you would put on it.

The matrix

Ordered by community size to begin with, because how findable help is outlives any one release; sort by score, by integrations or by any one of the six criteria instead; narrow by licensing model or by the capabilities you need — including CalDAV, which decides whether the tool reaches the phone and calendar you already use; expand a row for all six scores and the reasoning behind each one. Where a capability sits behind a paid tier, a plugin or a separate add-on, the cell says so rather than showing a tick — and the filters below honour that distinction.

Twenty-five projects, six scored criteria, five capability checks and a sourced record for each, compiled 17 September 2026 from project documentation, repositories and release histories; corrections are dated when they land. Scores are editorial judgements on a 1–5 scale, not benchmarks. Community size is a proxy drawn from repository signals, release cadence and ecosystem scale, not a count of deployments. Star counts were read from the repository APIs on that date and rounded to one decimal; a † on a figure marks a repository that does not map cleanly onto the product, and says so on hover. Integration figures estimate meaningful packaged connections, documented importers and marketplace plugins; API and webhook extensibility is recorded separately in each project’s record.

Where to start

A matrix tells you what each project does, not which one is yours. These are the routes the research actually supports, and every one of them is reversible by reading the record behind it.

A 50–5,000 person organisation replacing Jira or Microsoft Project
Start the proof of concept with OpenProject and Plane. OpenProject has the stronger classic portfolio, cost and governance pedigree and first-class Helm deployment; Plane has the more contemporary product-development interface and a much larger advertised integration surface.
A small or mid-size mixed team where usability outweighs governance
Leantime. Ordinary tasks, Kanban, timeline planning, personal work management and native time tracking, without feeling primarily like an issue tracker.
A homelab, a personal setup, or anyone minimising lock-in
Vikunja, provided the time-tracking split is acceptable: that capability now sits in the separate Pro tier rather than the AGPL core. Docker or a native binary, CalDAV, and documented migration in and out.
A team that genuinely runs Scrum or Kanban rather than generic task lists
Taiga. Backlogs, sprint planning, task boards, burndowns, WIP limits and swimlanes. The absence of native Gantt, calendar and time tracking is specialisation, not neglect — but it is a hard exclusion if you need them.
A Trello replacement
Largely philosophical. PLANKA gives the more polished board-first product; Kanboard wins decisively on licensing simplicity and technical independence — MIT, SQLite by default, almost no operational surface.
An organisation already committed to Nextcloud
Test Nextcloud Deck before deploying a second platform. Nextcloud added official Gantt support in June 2026, which makes older comparisons wrong. Do not deploy the whole Nextcloud stack purely to obtain a Kanban board.
One person, no server, and no intention of running one
Super Productivity if the work already lives in Jira, GitHub or GitLab — it pulls the issues in and times them, with nothing to deploy. Logseq if your tasks are really notes, and you want them as Markdown files you could still read in twenty years. Taskwarrior if you live in a terminal, accepting that the browser comes from somebody else’s client.
An agency or studio billing client hours
Kimai is the strongest of the three: rates, budgets, invoices and strict per-customer visibility, with twenty years behind it. Titra is the lighter option if you only need time against projects. Worklenz if you would rather run one tool for the tasks and the billing than two that integrate.
A team already running the work out of a spreadsheet
Grist or NocoDB, and the choice is about where the data should live. Grist keeps a document as a SQLite file with access rules down to the cell; NocoDB points at a PostgreSQL database you already run and leaves it there. Both give you a board. Neither gives you a sprint, a dependency or a timeline unless you build it, so be honest about whether the spreadsheet was the problem.
Documents and tasks that need to sit in the same place
AppFlowy is the closest to Notion and self-hosts on an AGPL core, though check that what you need is not in an AI or vault tier. AFFiNE has the better whiteboard and the worse licence: the client is open, the self-hosted backend is not. Nextcloud Deck remains the answer if documents already mean Nextcloud.
Large existing custom workflows and a strong internal IT team
Redmine. The weakest interface among the mature options, and the strongest survivability: configurable issue workflows, custom fields, plugins, multiple databases and nearly two decades of continuity. Old is not abandoned — it shipped three supported-version updates in August 2026.

How the scores work

Six criteria, each scored from 1 to 5, each carrying a written justification on every project. Publishing the reasoning matters more than the number: it lets you disagree with one assessment rather than dismissing the table.

Ease of deployment
Containers and packages, dependency count, operational complexity, upgrade burden and the state of the documentation.
Ease of use
Interface clarity, learning curve, conceptual overhead and whether non-specialists can live in it.
Enterprise features
Permissions, identity, audit and governance, portfolio reporting, scalability and administration.
Interface flexibility
How many genuinely useful views exist, plus workflow and custom-field options, dashboards, filters and extension points.
Data sovereignty
Whether you can run it independently, read its source, and keep control of the application and its data infrastructure.
Portability
APIs and exports, conventional storage and database choices, licensing constraints, and how realistically you could leave.

Each criterion is scored from 1 to 5. The Score column shows their unweighted mean; it is an editorial summary, not a measure of which tool is best for everyone. The directory opens by community size, largest first, with alphabetical ties. Sort by a criterion to see its score in the column and compare what matters to you.

Each record carries a Confidence value covering the licensing and capability evidence and the review depth of the scores. High indicates stronger evidence and review; Medium-high flags a remaining qualification, such as an uncertain edition boundary; Medium generally marks a first-pass assessment. Read the caveat and sources alongside the label.

Licensing and paid features

Labels describe the assessed code and edition, using the project’s licence files and edition documentation. Paid availability is recorded separately in the feature marks and record notes. OpenProject, for example, publishes its Enterprise add-ons under GPLv3, so paid add-ons alone do not make it open core.

FOSS
The assessed software uses a recognised free and open-source licence. Paid hosting, support or GPL-licensed add-ons do not change that classification; FOSS does not mean every feature is available in the free edition.
Open core
An open-source core is offered alongside extensions or editions under proprietary or other non-open-source terms. The distinction is the licence of those additions, not whether the free edition feels complete.
Source-available
The assessed edition exposes source code under terms that restrict open-source freedoms, such as use, modification or redistribution. Read the licence and edition caveat; visible source and permission to self-host do not by themselves make software open source.

Questions

What is todoi.org?

A volunteer-run directory for teams working out which task manager to commit to. It compares twenty-five browser-based projects whose source you can read, and publishes the reasoning behind every judgement so you can assess how each score was reached. There is nothing to sign up for and no project pays to be listed.

What separates open source, open core and source-available?

These labels describe different licence terms. “I can read the source”, “I can host it myself” and “it is open source” are three separate claims, and a project can satisfy one without the others. The Licensing column keeps them apart, and the feature marks show where a capability sits behind a paid edition rather than in the core you can actually run.

How were the 1–5 scores decided?

By reading documentation, repositories and release histories against the six criteria described above, then writing a justification for every individual score. They are informed editorial judgements, not benchmarks, and two reasonable people would score some of these differently. Expand any row to read why a project got the number it did.

Why is community size a category rather than a number?

No single metric captures community size. Repository stars, forks, contributors, container pulls, release cadence and forum activity all measure different things, and none of them is a deployment count. The star column beside it shows one readily available signal alongside that broader assessment: Redmine sits in the top band on 6.0k stars, because GitHub holds a mirror of a project that predates it, and Plane sits in the same band on 59.5k. Both figures are accurate. Neither is an installation count.

Why are the integration counts estimates?

Counts include documented integrations, importers and plugins. API and webhook access is listed separately, because it describes what you could build rather than a ready-made connection.

Are all twenty-five assessed to the same depth?

No, and the Confidence value on every record says which is which. The original eleven were researched first and read twice. The fourteen added on 17 September 2026 carry checked facts and a considered first-pass score, read once — most of them are marked Medium for that reason. Each assessment includes its reasoning and sources. If you find an error, send a correction with a supporting source.

Does a project have to be self-hostable to be listed?

No. The two rules are a browser interface and open, or partly open, source. Most entries here are server software you run yourself, because that is what most readers arrive looking for. But a local-first tool that keeps your data in files on your own disk answers the same question about control by a different route, and Logseq, Super Productivity and Taskwarrior are on record for that reason.

How current is this?

Compiled on 17 September 2026, and each record carries its own caveat about what was changing at the time. Two are worth knowing about before you read further: Nextcloud announced official Gantt support for Deck in June 2026, which makes older comparisons wrong, and the hosted Huly service was announced for shutdown around 20 July 2026 while self-hosting continued.

Corrections and additions

This directory is maintained by volunteers, and the field moves. A licence changes, a capability shifts from the core into a paid tier, a hosted service shuts down while the self-hosted project carries on. If a record here is wrong, send the correction with a source and it will be checked against the same criteria as everything else.

What gets listed

Two rules, and no others. A system has to be usable in a browser — its own web interface, a progressive web app, or a documented browser client — and its source has to be open at least in part: a recognised free licence, an open core, or source you can read and run. Being small, new, unfashionable or awkward to install is not a reason to be left out. Being unverifiable is.

A project that passes both rules gets a row, the same six criteria and the same written reasoning as everything already here — there is no waiting area and no second tier. What a new entry carries instead is a lower Confidence value until a second reader has been through it. Nobody pays to be listed, and nobody can pay to be scored differently.
